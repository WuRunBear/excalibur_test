**验收**：工作区改坏实体 JSON → 保存时报错并定位行/字段；改对后保存成功且本体文件未变。

> ✅ **S2 已完成（2026-09-20，提交于 feat/admin-platform）**
> - **Spike-2 结论**：`tools/validate.ts` 的 `validate()` 失败路径有 `process.exit(1)` CLI 副作用，不可同进程复用 → 改为直接 import 幂等的 `bootstrapFramework()` + `loadGameDefinition()` 核心函数（免子进程兜底）。**实测额外发现**：`loadGameDefinition` 对缺失 game.json 会静默回退 `createDefaultGameDefinition()`——`validateWholeConfig` 已加存在性预检防御。
> - **实现要点**：zod 双实例问题（本体 schema 与 server 的 zod 为不同 pnpm 实例，类类型不兼容）→ 路由表用结构化接口 `SafeParseLike` 适配；活动工作区持久化到 `server/workspaces/.active-workspace.json`（tsx watch 重启不丢）；路径穿越防护（resolve 必须落在工作区 game/ 内）。
> - **集成修复**：S1 CORS 中间件 Allow-Methods 缺 PUT/PATCH/DELETE（S2 契约新方法预检必挂）→ 已补全。
> - **验收证据**：9 步验收序列全 PASS——创建工作区（fingerprint=883a07d5…）→ 配置树 → 读 wolf.json → 坏 JSON（删 kind/components）被 422 拒绝且 errors 含 jsonPath → 复原写回 → changes 哈希级归零 → 整体校验通过（实体 33/行为 4/规则 9/item 16/地图 5）→ 路径穿越被拒 → 删除工作区；本体 `git status` 恒为 0。
> - **web 侧**：WorkspaceView（卡片栅格/改动抽屉/三色状态 tag）+ ConfigView（Monaco + admin-light 主题 + 保存链错误面板 + Monaco marker 跳行 + dirty 守卫 + 整体校验结果条）；Monaco 0.56 以 `editor.api` 子路径按需引入（worker 独立 chunk）。
> - **已知限制**：部分 JSON 语法错误消息无行号（Node 短消息）；PUT 可新建文件（契约未禁止）；工作区删除为硬删除。
