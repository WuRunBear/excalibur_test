# 执行计划 — 游戏服务端可视化管理平台

> 依据：《PRD-游戏服务端可视化管理平台.md》v2.3（载体：excalibur_test 整体重构为管理平台，不受其既有架构约束）
> 原则：每阶段结束**可运行可验收**；S1 先用最小 spike 验证两个技术前提（tsx 别名解析、预览实例环境变量），失败即按回退策略调整再继续。
> 文档版本：v1.2（2026-09-20）

## 阶段总览与依赖

```
S1 重构骨架与实例管理 ──► S2 工作区与配置编辑 ──► S3 预览闭环 ──► S4 落盘
                                                          │
                                                          ├──► S5 地图工具（依赖 S2）
                                                          ├──► S6 存档与注册表（依赖 S1）
                                                          └──► S7 游戏观察视图（依赖 S3）
```

S5/S6/S7 在 S4 完成后可按需调整顺序并行推进。

---

## S1 重构骨架与实例管理

**目标**：excalibur_test 重构为管理平台 monorepo（根 = workspace 壳，`server/` + `web/` 双包平级），跑通"网页启停游戏进程 + 实时日志"；工程检查链适配新结构后全绿。

任务：
- [ ] **先迁后改（第一步）**：当前前端项目**原样复制**到 `web/`（package.json、src/、index.html、vite.config、tsconfig、prettier 等全量），迁移后立即验证 `pnpm dev` 可运行、`pnpm check:all` 全绿——这是后续一切改造的前提
- [ ] workspace 化：`pnpm-workspace.yaml` 改 `packages: ['server', 'web']`；根 package.json 改为 workspace 壳（公共脚本：一键起两端、schema:sync 等）；web 包脚本路径相应修正
- [ ] web 侧增量改造（保留现有架构，不重写）：新增管理 views 与 admin 组件；`modules/net`、`modules/maprender` 由原 game 域**移动+重命名**复用（实现不变，仅加连接地址参数化）；PlayView 由原 GameView 适配（连接可选正式/预览实例）；删除仅限 demo 残留（counter store、占位组件）；bridge/MainLayout/路由结构保留并在其上扩展
- [ ] 引入 Element Plus + `web/src/styles/element-theme.scss`（管理平台新增页面使用；游戏页继续用 pixelium）
- [ ] **Spike-1（立即验证）**：server 的 tsconfig 完整复制本体 paths 别名（`framework/*` 等十余个，指向 `../../game_server_test/framework/*`），`gameBridge/` 写一行 `import ... from "framework/api"` 跑通 tsx，确认别名解析与依赖版本（bitecs/zod/check2d/mistreevous/winston 同版本安装）
- [ ] `server/src/config.ts`：`GAME_ROOT`（默认 `../../game_server_test`，与 schema:sync 约定一致）、端口 3100
- [ ] `instanceManager.ts`：双实例进程管理——spawn（Windows `pnpm.cmd`）、env 注入、状态机 `stopped|running|crashed`、`taskkill /T /F` 树杀、退出码归因、崩溃事件
- [ ] `routes/process.ts`：启动/停止/重启/状态 REST
- [ ] `logStream.ts`：tail `logs/game.log` + 进程 stdout/stderr → WS 推送（带实例标识）
- [ ] `DashboardView`：正式实例状态卡 + 启停按钮；`LogConsole` 组件（WS 追加、暂停/清屏/级别过滤）
- [ ] 预览实例管理能力（暂指向本体配置）：role=`preview` 的 spawn/停止/状态

**验收**：浏览器启停正式与预览实例、日志实时滚动；kill 进程后前端显示"崩溃 + 退出码"；`pnpm check:all`（适配新结构）全绿；PlayView 冒烟可连本体。

## S2 工作区与配置编辑

**目标**：工作区镜像 + 编辑器 + 校验链，保存只写工作区。

任务：
- [ ] `workspaceService.ts`：新建（本体 `game/` 全量复制）/ 列表 / 切换活动工作区 / 重命名 / 删除；基准指纹 = 复制时文件清单 + 内容哈希
- [ ] `routes/workspace.ts` + `WorkspaceView`（列表/新建/切换）
- [ ] `configService.ts`：工作区文件树 / 读 / 写；schema 路由表（`game.json`→GameDefinitionSchema、`entities/*.json`→ArchetypeSchema、`maps/registry.json`→MapRegistrySchema、behaviors/dialogues/quests/rules/items 各归其位）
- [ ] 文件级校验 API：zod safeParse → 结构化错误（JSON 路径 + 消息）
- [ ] **Spike-2**：整体校验复用方式——优先同进程 import `tools/validate.ts` 核心函数（需无 CLI 副作用），否则子进程 `pnpm tools validate` + `GAME_CONFIG_PATH` 指向工作区
- [ ] `ConfigView`：目录树 + Monaco（JSON 高亮/格式化）+ 保存链（校验失败定位回显）+ "整体校验"结果面板

**验收**：工作区改坏实体 JSON → 保存时报错并定位行/字段；改对后保存成功且本体文件未变。

## S3 预览闭环

**目标**：落盘前在预览实例看真实运行效果。

任务：
- [ ] **Spike-3（关键实测）**：`GAME_CONFIG_PATH` 指向工作区 `game/game.json` 启动游戏，确认 entities/maps 等按该路径解析；存在按 cwd 解析的部分则 spawn `cwd` 兜底到工作区 `game/`
- [ ] 预览实例 env 注入：`GAME_CONFIG_PATH=<workspace>/game/game.json`、`SAVE_DIR=<workspace>/.preview-saves/`、`PORT=3200`
- [ ] 仪表盘双实例卡：正式/预览并列，各自状态、启停、日志页签
- [ ] 配置上下文卡：正式实例配置指纹 vs 活动工作区指纹对比，不一致提示
- [ ] 联调：编辑 → 重启预览 → 日志/状态可见

**验收**：改工作区配置 → 预览实例重启后生效（日志可证），本体目录与正式实例零改动。

## S4 落盘

**目标**：diff 审查 → 备份 → 写回本体 → 可回滚。

任务：
- [ ] `applyService.ts`：工作区 vs 本体逐文件对比（added/modified/deleted + 内容 diff，后端用 `diff` 包计算）；前置校验（所选文件必须全过校验链）
- [ ] 备份：写回前将被覆盖/删除文件存 `server/backups/<时间戳>/`（含 manifest）
- [ ] 回滚：按 backupId 将备份写回本体
- [ ] `routes/apply.ts`：diff 预览 / 执行落盘 / 备份列表 / 回滚
- [ ] 前端落盘审查页（挂 `WorkspaceView`）：Monaco DiffViewer + 按文件勾选（`valid=false` 禁选）+ 确认对话框 + 备份回执 + "落盘后重启正式实例"引导
- [ ] 落盘后状态同步（已落盘文件标记、基准指纹更新）

**验收**：勾选部分文件落盘 → 本体仅所选文件变更，备份可一键回滚；含校验失败文件时无法落盘。

## S5 地图工具

**目标**：地图生成/预览/导出/对比（高复用 mapCodec）。

任务：
- [ ] `mapService.ts`：解析 `maps/registry.json`（工作区/本体双源）；调 `buildMapGeometry` 产 geometry snapshot；调 `exportGeometryArtifacts` 产 PNG/JSON；色表参数支持
- [ ] `routes/maps.ts`：列表 / 生成预览 / 导出下载
- [ ] `MapView`：地图列表（key + 管道积木链）、PNG 预览、元信息（尺寸/区域面积/version 指纹）
- [ ] 叠加视图：复用 mapCodec 几何重组逻辑渲染 walkable 底色、region 边界着色、演化规则点位
- [ ] 同图对比：工作区 vs 本体并排

**验收**：工作区改地图配置 → 不落盘直接生成新预览；与本体同图并排可见差异。

## S6 存档与注册表

**目标**：存档全操作 + 注册表速查。

任务：
- [ ] `saveService.ts`：扫描 `data/saves/` 及预览存档目录；解析 WorldRecord 摘要（saveId/tick/savedAt/地图数/按 kind 实体计数）
- [ ] `routes/saves.ts`：列表 / 详情 / 删除 / 下载备份 / 恢复（替换活跃存档，提示重启正式实例）
- [ ] `SaveView`：正式 + 预览存档双页签；删除二次确认
- [ ] `routes/registries.ts`：调 `listRegisteredSystems/Archetypes/Actions/Components/MapGenerators`
- [ ] `RegistryView`：五类注册项分组展示 + 搜索过滤

**验收**：存档浏览/删除/恢复/备份全通；注册表与 `pnpm tools list-registries` 输出一致。

## S7 游戏观察视图

**目标**：PlayView 连接任意实例观察运行效果 + 趋势图表。

任务：
- [ ] net 模块连接地址参数化：正式（:3000）/预览（:3200）下拉切换，一套客户端能力观察任意实例
- [ ] PlayView：Excalibur 渲染地图与实体实时状态（位置/朝向/血条），按地图切换；支持发送移动输入以主动验证 AI/战斗/交互效果
- [ ] ECharts 趋势：tick 速率、实体总数时序
- [ ] 仪表盘接入

**验收**：PlayView 分别连正式/预览实例均可实时渲染实体移动并可操作；趋势图滚动更新。

## 里程碑验收清单（全量）

1. 配置调试闭环：新建工作区 → 编辑（校验报错定位）→ 预览实例看效果（本体零污染）→ 落盘（diff 勾选 + 备份）→ 正式实例重启生效 → 备份回滚可用
2. 地图：工作区改动即时预览、叠加视图、同图对比、导出
3. 存档：浏览/详情/删除/恢复/备份，预览存档隔离
4. 监控：双实例状态卡、实时日志、崩溃告警、PlayView 观察与趋势图
5. 边界：`game_server_test` 仓库零代码改动（git status 仅存档/日志等运行时产物）；excalibur_test 新结构下 `pnpm check:all` 全绿

## 技术前提与回退策略

| 前提 | 验证点 | 回退策略 |
|---|---|---|
| tsx 解析跨仓 paths（Spike-1） | S1 首日 | 改"本体 build 后 file: 依赖引 dist"（唯一可能触碰本体的情形，需先确认） |
| GAME_CONFIG_PATH 目录语义（Spike-3） | S3 首日 | spawn `cwd` 指向工作区 `game/` 兜底；仍不行用 junction 符号链接 |
| 整体校验复用（Spike-2） | S2 | 子进程 CLI 兜底 |
